Fun fact: Richard Bellman named it in the 1950s. “Programming” meant planning with a table, not coding, and he picked “dynamic” partly because it sounded impressive to his bosses.

Now with proper names

What is Dynamic Programming?

Solve a problem by combining answers to smaller subproblems, solving each subproblem only once and storing its answer.

A problem is a good fit for DP when it has both of these properties:

Optimal Substructure

The best answer to the big problem is built from the best answers to smaller subproblems.

best(6) = 1 + min(best(5), best(3), best(2))

Overlapping Subproblems

The same subproblems come up again and again, so storing their answers saves lots of work.

best(2) was asked 4 times in the tree

Missing optimal substructure? DP won't work. Missing overlap? Plain recursion (divide & conquer) is already enough.

The classic example

Fibonacci: watch the tree shrink

fib(n) = fib(n−1) + fib(n−2)
fib(0) = 0, fib(1) = 1
calls for fib(6): 1
fib(40) without memo: about 331 million calls.
With memo: just 79.
Two ways to write DP

Top-Down vs Bottom-Up

Top-Down · Memoization

Write the natural recursion. Before solving, check the notebook.

memo = array filled with EMPTY

function fib(n):
    if n ≤ 1: return n
    if memo[n] ≠ EMPTY: return memo[n]
    memo[n] = fib(n − 1) + fib(n − 2)
    return memo[n]
✔ Easy to write from the recurrence
✔ Only solves subproblems it needs
✘ Deep recursion can overflow the stack

Bottom-Up · Tabulation

Start from the smallest answers and fill the table in order.

dp[0] = 0
dp[1] = 1
for i = 2 to n:
    dp[i] = dp[i − 1] + dp[i − 2]
return dp[n]
✔ No recursion, usually faster
✔ Easy to save memory (keep only the last rows)
✘ You must figure out the filling order
Same answers, same table. Top-down asks “what do I need?”; bottom-up asks “what can I build next?”

Filling the table: skip it or take it?

dp[0][w] = 0 for every w
for i = 1 to n:
  for w = 0 to W:
    dp[i][w] = dp[i−1][w]               // skip
    if weight[i] ≤ w:                   // take
      dp[i][w] = max(dp[i][w],
          dp[i−1][w − weight[i]] + value[i])
answer = dp[n][W]
Problem 2 · Grid Paths

How many ways can the robot reach the flag?

The robot starts at S, moves only right or down, and can't go through rocks.

Every path into a cell arrives from above or from the left.
ways[r][c] = ways[r−1][c] + ways[r][c−1]
Rock → 0 ways. Start → 1 way.
